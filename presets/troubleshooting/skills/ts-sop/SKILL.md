# RCA SOP（结构化故障根因分析）

严格顺序执行；每一步产物落工作区（`incidents/<日期>-<摘要>/`），证据随步骤沉淀。

## 流程

1. **澄清现象**：现象是什么、影响面（谁在用/什么功能）、起止时间、频率。现象不清 → 先问，不猜。
2. **建立时间线**：故障开始/结束/关键变化点；与变更、发布、重启时间对齐。
3. **先查变更（CMDB）**：故障窗口内该资源/区域有无变更发布（部署/配置/迁移）。**变更优先于指标**——大多数故障由变更引起。
4. **看指标**：CPU/内存/连接数/QPS/错误率/延迟，故障窗口 vs 基线对比。查证"指标真的异常"而不是"应该异常"。
5. **追调用链**：跨服务请求路径，定位失败节点与耗时分布（慢在哪一跳、错在哪一环）。
6. **深挖日志**：故障窗口内错误/异常/关键事件；从链路指到的节点日志入手。
7. **检索知识库**：同类故障的历史处置与经验（先查后猜）。
8. **收敛根因**：证据链 → 根因（区分 事实/推断/建议）；根因必须被证据支持，够不到就说"证据不足 + 下一步验证计划"。
9. **生成报告**：故障概述 → 影响范围 → 时间线 → 证据清单（按源分类，标注来源类型/查询条件/关键结果）→ 根因分析 → 处置与恢复 → 后续建议。

## 纪律

- 未查数据源不得臆测根因；工具失败如实说明，不得当作"无异常数据"。
- 每一步证据落盘（命令+输出），报告引用证据而非复述。
- 处置动作（重启/回滚/改配置）先说明影响面与回滚预案，经用户确认后执行。
- 结束后经验沉淀：通用结论 → `sop/通用故障模式/`；本机特征 → `sop/本机经验/`。
