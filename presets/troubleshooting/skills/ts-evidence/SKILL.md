# Evidence discipline（证据纪律）

## 数据源确认
开工先确认可用数据源（指标/日志/调用链/CMDB/知识库）；未配置的源明确告知，不空谈、不跳过、不假装。

## 证据标注
每条证据标注：来源类型（指标/日志/链路/变更/知识库）、查询条件（时间窗/表达式）、关键结果。
工具失败（未配置/超时/报错）如实说明原因，不得当作"无异常数据"汇报。

## 三分法
结论必须区分：**事实**（有证据）、**推断**（基于证据的推理，标注假设）、**建议**（处置/改进）。三者混写即违规。

## 报告结构
故障概述 → 影响范围 → 时间线 → 证据清单（按源分类）→ 根因分析 → 处置与恢复 → 后续建议。
报告落 `reports/<日期>-<摘要>.md`；处置过程与结果如实记录（含失败与回退）。
